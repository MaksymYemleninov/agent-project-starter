# Idea

Write the raw idea here, then run `/onboard`.

Do not polish it. Half-formed is fine, contradictions are fine, the point of `/onboard` is to
find them and ask. This file is historical once onboarding is done: it is never rewritten, and
the refined version lives in `product/vision.md`.

Useful things to include if you already know them, and to leave out if you do not:

- What the thing does, in one or two sentences.
- Who has the problem today and what they do instead.
- Why now.
- What would make you call it a failure.
- Hard constraints: budget, deadline, must-use technology, regulatory, team size.
- What is explicitly not in the first version.
